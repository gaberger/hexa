# ADR-2611050000: Template-Driven Telemetry Rendering

## Status
Proposed

## Context
The introduction of the `SemanticCompressor` in `hexa-infer` allows the system to handle massive conversation histories by recursively summarizing older turns. While this is technically successful, the operator has no visibility into the "Context Health"—they don't know if the agent is currently operating on a highly compressed history or if the compression ratio is degrading.

Currently, `InferenceResponse` in `hexa-core` has been updated to include a `telemetry` map, but this data is not surfaced in the `hexa-cli` UI.

## Decision
We will implement a template-driven telemetry rendering system in `hexa-cli` to surface these metrics in the status line during `hexa run` and `hexa loop`.

1. **Telemetry Asset**: Define a new asset `hexa-cli/assets/telemetry.json` that maps telemetry keys to visual representations (an icon and a label each).
2. **Formatter Logic**: Implement a `telemetry_badge` function in `hexa-cli/src/fmt.rs` that consumes the `telemetry` map and the asset to produce a formatted string.
3. **Status Line Integration**: Update the primary execution loop in `hexa-cli` to append these badges to the active status line.

The API, all in `hexa-cli/src/fmt.rs` (the tests call it as `hexa_cli::fmt::…`):

```rust
/// How one telemetry key is shown: `{icon} {label}: {value}`.
pub struct TelemetryEntry { pub icon: String, pub label: String }

/// The asset, keyed by telemetry key.
pub struct TelemetryAsset { /* private */ }
impl TelemetryAsset {
    /// Parse the text of `telemetry.json`. Never fails: malformed text gives an
    /// empty asset and a warning on stderr, so the binary starts regardless.
    pub fn parse(text: &str) -> TelemetryAsset;
    pub fn get(&self, key: &str) -> Option<&TelemetryEntry>;
}

/// One `{icon} {label}: {value}` per key the asset knows, in key order, joined
/// by a single space. A key the asset does not know is left out. Plain text:
/// the caller styles it. Empty when nothing is shown.
pub fn telemetry_badge(telemetry: &std::collections::HashMap<String, String>, asset: &TelemetryAsset) -> String;

/// `line`, then a space and `badge`; `line` unchanged when `badge` is empty, so
/// a quiet loop gains no trailing whitespace.
pub fn append_telemetry(line: &str, badge: &str) -> String;
```

An entry of `telemetry.json` has an `icon` and a `label`; the value is shown as the run reports it.

## Consequences
- **Positive**: Operators gain real-time visibility into the efficiency of the semantic compressor.
- **Positive**: UI formatting is decoupled from the binary, allowing for rapid iteration and project-specific customization via assets.
- **Negative**: Adds a small overhead to load the telemetry asset on startup.
- **Neutral**: Introduces a dependency on the `telemetry` map in the `InferenceResponse` contract.

## Gate

`cargo test -p hexa-cli --test adr_2611050000_spec`: the sealed tests of the spec's eight scenarios: the
asset parses and a malformed one yields an empty mapping, the badge renders full, partial, empty and
unknown-key telemetry, and the status line gains the badge without trailing whitespace.
