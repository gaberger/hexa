# ADR-2609211600: A reference is an import, whether or not it has an import line

**Status:** Accepted
**Date:** 2026-09-21
**Drivers:** `[[import_policy]]` (ADR-2609211430) judged only import *declarations*. Rust lets code name a crate inline with no `use` line, and TypeScript loads modules through expressions. Every inline form passed the shipped domain policy on `main` at `996628f`, including `std::fs::read`, which the policy explicitly denies. The rule the README states ("domain imports only domain") was walkable in one line.

## Context

Reproduced on `996628f` with the shipped `hexa-cli/assets/templates/ADR-rules.toml`, one file per case under `src/domain/`:

| Written in the domain | Before | After |
|---|---|---|
| `use sqlx::PgPool;` | error | error |
| `use std::fs;` | error (`deny`) | error |
| TS `import { Pool } from "pg"` | error | error |
| `pub fn c() { let _ = std::fs::read("x"); }` | **none** | error |
| `pub fn e() { let _ = ::sqlx::query("x"); }` | **none** | error |
| `pub fn f(_p: sqlx::PgPool) {}` | **none** | error |
| `#[tokio::main] async fn m() {}` | **none** | error |
| `pub fn q() { let _ = sqlx::query!("x"); }` | **none** | error |
| `extern crate sqlx;` | **none** | error |
| TS `const fs = require("node:fs")` | **none** | error |
| TS `await import("pg")` | **none** | error |
| TS `type P = import("pg").Pool` | **none** | error |
| TS `require(name)` with a variable | **none** | warning |
| `pub struct O; … O::new()` (local type) | none | none, **correctly** |

The cause was one input: `evaluate_import_policies` read only
`ast.extract_imports(...)`, which returns declarations. Classification
(`classify`, `judge`) was pure and correct for any path it was given, and was
simply never given these.

The inline forms are not exotic. Fully qualified paths are idiomatic Rust for
one-off calls, and they are what a model writes when it wants a call to work
without touching the top of the file. A `deny` entry for `std::fs` that
`std::fs::read` walks past is worse than no entry, because the rules file
claims a protection the tool does not give.

The hard part is not finding paths. Tree-sitter already parses them. The hard
part is not flagging local code: `O::new()`, `Self::make()`, `Ordering::Less`
after a `use`, and enum variants all have a first segment that `classify`
would call External. An inline path can only be judged when its first segment
is known to name something outside the project.

## Decision

1. **An inline reference is judged exactly as a `use` of the same path would
   be.** No new policy fields and no new semantics. `allow`, `deny`, the
   standard-library rule and segment-boundary matching apply unchanged.

2. **Rust: a path is a reference when its first segment names something
   outside the project, and only then** — `std`/`core`/`alloc`, or a key of
   `[dependencies]`, `[dev-dependencies]`, `[build-dependencies]` or
   `[workspace.dependencies]`, normalised `-` to `_`. The **key** is used, not
   `package =`, because the key is the name code writes. Everything else,
   including `crate`, `self`, `super`, `Self`, local types, modules and enum
   variants, is not a reference.

3. **Rust: the positions read are** expression paths, type paths (generic
   arguments included), attribute paths, macro invocation paths, and
   `extern crate` declarations. `extern crate x as y;` is judged as `x`.

4. **TypeScript: a string-literal module specifier is an import in any
   syntactic form** — `require("x")`, `import("x")` as an expression, and
   `import("x")` in a type position.

5. **What cannot be read is reported, not skipped.** A load with a non-literal
   argument produces a **warning**, so it does not move the grade
   (ADR-2609211430 §1) and `--strict` fails on it.

6. **Go needs no change.** Go cannot name a package without importing it.
   `plugin` is added to the shipped Go `deny`, since loading code at run time
   is infrastructure by definition.

7. **Each site is reported once**, keyed on file, line and the name that
   leaves the project.

## Consequences

- **Grades drop where the domain reaches out inline.** Each site costs 10
  points at `severity = "error"`. `docs/UPGRADING.md` gains an entry naming
  the new forms.
- **Test code inside the domain is judged too.** A `#[cfg(test)] mod tests`
  calling `proptest::…` inline is now a finding, exactly as `use proptest::…`
  in the same place already was. No test exemption is added, because the `use`
  path has none either.
- **Dependency names come from the manifest.** A path whose first segment
  coincides with a dependency name but is a local module is flagged; that is
  rare and self-inflicted, and the finding names what it matched.
- **What remains unseen** is code generated by a macro from an allowed crate,
  reflection, and FFI. The README's limits section lists exactly these three,
  and says computed-name loads are reported as warnings rather than skipped.

## Implementation

- `hexa-analysis/src/treesitter_adapter.rs`: `extract_module_references`,
  returning `ModuleReference { raw_path, line, kind }`.
- `hexa-analysis/src/import_policy.rs`: `ProjectNames::rust_dependencies` and
  the pure `names_external`.
- `hexa-cli/src/commands/analyze.rs`: dependency keys in `project_names`;
  `evaluate_import_policies` judges declarations and references together,
  deduped per site.
- `hexa-cli/assets/templates/ADR-rules.toml`: `plugin` in the Go `deny`.

**Deviation from the plan.** The new extractor is called
`extract_module_references`, not `extract_references`: that name is already on
`AstPort` with an unrelated meaning (a name-to-count map used by the
dead-export detector). It is a free function rather than a port method, so
adding it does not change the trait every adapter implements.

**Gate:** `cargo test -p hexa-cli --test domain_import_references` — 21 cases
against the **shipped** rules file, so it tests what a scaffolded project
gets. Verified against `996628f`: 14 of 18 failed before the change, and the
4 that passed were the negative controls. The Go cases were added after a
review question — the first draft covered Rust and TypeScript only, which
would have left §6's claim and the new `plugin` entry untested. The `plugin`
case was confirmed to fail with that entry commented out.

Negative controls, which pass on both sides: local types, `Self`, an enum
variant, a local module, `crate::`, a relative TypeScript import, a Go import
of the project's own module, and hexa's own tree still grading A+.
