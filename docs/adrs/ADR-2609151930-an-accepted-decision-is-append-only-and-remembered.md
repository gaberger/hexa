# ADR-2609151930: An accepted decision is append-only, and memory knows it

**Status:** Proposed
**Date:** 2026-09-15
**Drivers:** 113 of the 140 ADR ids cited in this codebase have no file. Six ADRs have been rewritten in place since creation, four of them today. No memory entry names an ADR and no ADR names a memory entry. Investigation: `docs/analysis/2609151900-adrs-as-memory-investigation.md`.

## Context

The project's rule is that an ADR is history: prose that never claims to
describe the present, and therefore may stay unexecutable. History that can be
edited in place is not history. Today `hexa adr accept`, `complete`,
`supersede`, and `docs migrate-adr` all rewrite the ADR file, and nothing
checks that the body of an Accepted decision is the body that was accepted.

Separately, `hexa memory` is the store the executor reads before every task,
ranked by code-graph relevance. It holds two lessons. The decisions that would
actually shape a change live in `docs/adrs/`, which the executor never reads
beyond three filenames at session start.

## Decision

1. **The ledger is append-only.** `docs/adrs/ledger.jsonl` records one event
   per lifecycle change: `{id, event, ts, body_sha256, by}`. `accept` appends
   an event carrying the hash of the body below the frontmatter. `complete`,
   `supersede`, and `abandon` append events; they do not rewrite `## Context`,
   `## Decision`, or `## Consequences`. The `Status:` line in the file is a
   rendering of the ledger, regenerated by `hexa adr reindex`, never edited by
   hand.
2. **The doctor fails on a changed body or a dangling citation.** For every
   ADR with an `accept` event, the body hash must match. For every `ADR-…` id
   in code, docs, `CODEOWNERS`, and `.hexa/*.toml`, a file must exist. A
   citation to a decision whose text was not carried into this repository is
   satisfied by a stub ADR with status `Historical` that records what the
   citing code says the decision was.
3. **Accepting an ADR writes memory.** `hexa adr accept <id>` stores
   `adr:<id>` = `{title, decision, gate, commit}` through the memory store. A
   later `accept` of the same id supersedes the line; memory's newest-wins
   read already handles that.
4. **A lesson names its decision.** `hexa memory store lesson:<topic>` takes
   `--adr <id>` and records it in the value. A lesson without an ADR is
   accepted with a warning that names the ADR the `governing` verb would
   assign to the path, if any.
5. **The executor reads both.** `gather_context` filters memory to `lesson:`
   and `adr:` prefixes before ranking, and the session fingerprint selects
   ADRs by `Applies-To` match on the task's file when one exists, falling back
   to the newest three.
6. **The gate runner says why.** `hexa adr gates` prefixes PATH with
   `~/.cargo/bin` when present, classifies a cargo that cannot read the lock
   file or a network gate that cannot reach its host as *unrunnable here*, and
   prints the last ten lines of a real failure.

## Consequences

- An Accepted ADR's decision text cannot drift without the doctor and CI
  failing. Corrections are a superseding ADR, which is what the pipeline
  already says they should be.
- Every citation resolves. The reader who follows "ADR-2026-06-04-1740 Path A"
  lands on a stub that says the text is gone and what the code believes the
  decision was. That is less than the original and more than nothing.
- Memory stops being decorative for decisions: the top-six context an agent
  gets before editing a file can include the ADR that governs the file.
- `hexa adr gates` becomes a regression suite that either passes, fails with
  output, or says it could not run here. The 0-passed row in the
  investigation cannot recur silently.
- Cost: a ledger file to keep, a hash to compute on accept, a memory write on
  accept, one flag on `memory store`, and a backfill of `Applies-To` that is
  its own workplan.

## Implementation

Gate, written before the code:

```bash
cargo test -p hexa-cli --lib adr_ledger && cargo test -p hexa-cli --lib adr_citations && cargo test -p hexa-exec --lib lesson_prefix_filter
```

Ordered by value per change:

1. `adr_citations` — doctor scans citations, fails on dangling. Stub ADRs for
   the 113 orphans, generated from the citing comments, reviewed by hand.
2. `adr gates` PATH and classification.
3. `adr_ledger` — ledger file, hash on accept, doctor check, `Status:`
   rendering.
4. `adr:<id>` memory write on accept; `--adr` on `memory store`.
5. `lesson_prefix_filter` in `gather_context`; `Applies-To` selection in the
   fingerprint.
